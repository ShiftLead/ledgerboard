## Should a board split keep putting a paragraph written below an item into the board's README with a warning, rather than attaching it?

**Kind:** decide
**Added:** 2026-11-16
**Session:** lb-designer
**Context:** TD-130 decision (paul)
**Due:** 2026-11-24
**Answers:** Go (default) — a session archives the entry and nothing is built | One more round — a session runs one more review round, then asks again | Hold: <note> — a session revises the design as your note says

- **Context:** In ledgerboard (the ledger and board formats agent-cadence and ShiftLead both use), TD-130 asks whether splitting an old single-file board into one file per item should attach a paragraph a session wrote a blank line below an item, such as an update with a new due date, to that item. The old format never counted it as the item's, so the split puts it at the end of the board's README with a warning (TD-129). The design keeps that: the split writes exactly what the old reader read, a rule telling an update from a note would be a guess, and the new item file could not even hold the paragraph as written. The session running each split reads the warnings and moves a real update into its item by hand. One review round ran the split on test boards and found nothing that would change the decision. Plain-words summary: docs/synopses/TD-130.md; the review record: docs/reviews/TD-130.md (PR #394).
- **Question:** Should the TD-130 design stand, so the split keeps such paragraphs in the README with a warning and nothing is built?
- **Recommended:** Go — the review found nothing that would change the decision, and attaching would mean guessing which paragraphs are updates. **Otherwise:** One more round, if you want another reviewer to read it; Hold with a note naming a shape you want attached, if you want the split to attach it.
