## Should the design that lets the merge check recognise a question a tool asks you get one more review round?

**Kind:** decide
**Added:** 2026-11-23
**Context:** TD-161 decision (paul)
**Due:** 2026-11-30
**Answers:** One more round (default) — a session runs one more review round on the unread fixes, then asks again | Go — a session files the build and the grinders build it | Hold: <note> — a session revises the design as your note says
**Decided:** 2026-11-23 by paul — One more round

- **Context:** ShiftLead's home tool now asks you about an entry by landing a small change at once with no review, and the weekly audit reports each as an unreviewed merge, which can hide a real one. This design adds a merge-check verdict that rebuilds the change and passes it only if it does nothing but hold that one entry back and ask. It ran four review rounds, finding 2, 1, 1 and 0 problems that would change the build, so the rounds ended by the stop rule. The closing check added two small refusals to the shared writing step, and no reviewer has read them. One choice to weigh: until ShiftLead takes the new release, questions about an entry that already has a work order or similar board item will often still show in the audit, because the check makes no exception for the older wording. Plain-words summary: docs/synopses/TD-161.md; the review record: docs/reviews/TD-161.md.
- **Question:** With the rounds ended and the last small fixes unread by any reviewer, should the design get one more review round before it is built?
- **Recommended:** One more round — the closing fixes change what the build writes and nobody has reviewed them, and a round is cheap next to building on an unread fix. Otherwise Go, if you accept those fixes as the check's own suggestions; Hold with a note, if you want the design changed.
