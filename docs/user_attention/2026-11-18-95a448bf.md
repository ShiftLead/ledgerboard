## Should the design that stops a separator line after an entry's question being read as part of it get one more review round?

**Kind:** decide
**Added:** 2026-11-18
**Session:** lb-designer
**Context:** TD-148 decision (paul)
**Due:** 2026-11-25
**Answers:** One more round (default) — a session runs one more review round on the unread fixes, then asks again | Go — a session files the build and the grinders build it | Hold: <note> — a session revises the design as your note says

- **Context:** In ledgerboard (the ledger and board formats agent-cadence and ShiftLead both use), TD-148 fixes how a separator line between two entries is read. Old single-file ledgers often put a horizontal line between entries, and the tools read it as the last line of the entry above, so a question at an entry's end is flagged as too long, is shown to you ending in that line, and its offered answers are refused; split files keep the line and later notes bury it. The design makes such a line, when it is an entry's very last line after a blank line, part of no section: every tool reads past it and every writer keeps it at the end, nothing deleted and no saved entry changing by a byte. It ran six review rounds, the most this kind of change gets, each building the rule in a scratch copy and testing it on many invented entries. The point that kept returning was hidden comments next to the line; round 3 settled it by deciding the rule with comments set aside, and later rounds only tightened edges and test descriptions. Round 6 and the closing check each found a problem that would change what the build writes (where one blank line goes when a note is added to an entry that is only the line, and a spec sentence still stating the older rule); both are fixed, and no reviewer has read the fixes. Problems that would change the build, per round: 3, 2, 3, 4, 3, 2; the closing check 1. Plain-words summary: docs/synopses/TD-148.md; the review record: docs/reviews/TD-148.md.
- **Question:** With the rule holding since round 3 and the last fixes unread by any reviewer, should the design get one more review round before it is built?
- **Recommended:** One more round — round 6's and the closing check's fixes change what the build writes and nobody has reviewed them; a round is cheap next to building on an unread fix. Otherwise Go, if you accept those fixes as the reviews' own suggestions; Hold with a note, if you want the design changed.
