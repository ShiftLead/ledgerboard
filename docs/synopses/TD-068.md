# TD-068: a writer for the title, and names in the wrong place

No writer can change an open entry's title today. The title lives only in the `## TD-n: title` heading, and the
nearest edits put the name somewhere else: `edit --section Title` adds a body paragraph and `set --field Title=…`
adds a header field, both under the old heading. A mistyped section name such as `edit --section Status` leaves a
paragraph that reads like a field and is not one. Nothing refuses these, and `check()` reports none of them.
ShiftLead met it on 2026-11-11, and deleted and refiled an entry to change its title, losing its Log.

**The retitle.** `ledger.py set TD-n --title "<new title>"` rewrites the heading and keeps the file's name, its
fields and its sections. It logs `retitled: was "<old title>"`, so the old title stays in the entry's history and
a search for it still finds the entry. It can go with other `set` flags in one call, as a split often needs. A
title that is empty, more than one line, or holds `<!--` is refused. The same title changes nothing. An HTML
comment in the old heading goes with the old title.

**Names in the wrong place.** Two kinds of name are treated as misplaced:
- **Misplaced section:** a body section named `Title`, or named after one of the format's own header fields
  (`Priority`, `Type`, `Added`, `Status`, `Blocked by`, `Part of`, `Escaped from`, `Id take`), or after a name
  the ledger's `Fields:` line declares.
- **Misplaced field:** a header field named `Title` or `Log`.

Then:
- `edit` refuses to add a misplaced section, and says to use `set`. It still replaces any section the entry
  already has, so a stray's words can be corrected.
- `edit --section <name> --remove` removes a misplaced section, and only those, so it never removes a Why, a Fix
  or a body Location. If the header lacks that field, it asks you to `set` it first, so the words are not lost.
- `set` refuses a `Title` or `Log` field. An empty value still removes one.
- `new` refuses the same names.
- `check()` notes each misplaced section and field once (`misplaced-name`, ℹ, never an error) and names the cure.

**What it leaves alone.** A body `Location` is where v2.7 puts it, so `edit` adds one whatever the header holds;
a retired header field such as `Location` or `Waits` keeps its existing `retired` flag. `Owner` and `Kind` are a
repo's own words, so they count as header fields only where the repo declares them. A body `Waits` or `Taken by`
paragraph is left alone and never flagged (accepted). A retitle that makes an entry's first Log line can move
the age of an old gate with no `gate added` line, as `note` already does (accepted). Two stray sections with the same name are flagged once and stay a person's hand fix.

**Release.** A minor, v2.8, which reads one thing differently: a Log line an older `note` wrote that starts
`retitled:` now reads as malformed (none is known; each consumer checks once with a grep). On a ledger with a `Fields:` line, a header `Title`
or `Log` is no longer flagged `undeclared-field` (an error on an edited entry); `check()` names it misplaced (ℹ)
instead. The board's item key and the canonical form are unchanged. One build, B1. Then agent-cadence's vendor PR and ShiftLead's sync PR, each
passing `set --title` and `edit --remove` through its wrapper. A retitle changes the heading's anchor, so a
hand-written link to the old anchor stops landing.

**The rounds.** Six rounds, to the cap. One topic kept coming back: which copy of a name is the stray when it
appears both in the header and in the body (F2, F28, F48, F56). It is settled by the narrow rule above: the
only strays are a body section named `Title` or after a header field, and a header `Title` or `Log` field. The
last round's design review found nothing that changes the build.
