# TD-128: a board split names a host written as a phrase

When a board in the old single-file form is split into one file per item, each item keeps the session that
wrote it and the machine it ran on. The format writes that machine as one word, its short host name. Some
hand-written items name it as a phrase instead, such as *on Pat's laptop*. The split keeps only the first word
(*Pat's*), as the format has always read it, and warns about the rest. Today the warning reads as if some other
text, like a branch name, was dropped, so nobody can tell that the machine's name itself was cut.

**The choice.** The machine name stays one word, as the format says, and only the warning changes. Where the
words right after the machine name continue it, before any comma or semicolon, the split now says *host kept to
its first word; not carried: laptop*, and names any other dropped text in a second warning, as today. The
warning cannot tell a machine named as a phrase from a machine name followed by other words without a comma, so it
says only what it knows: the first word was kept and the rest was not carried. The session running the split can
then fix the item by hand to the real machine name.

**Options set aside.** Letting the machine name hold spaces would change what every tool reading these files
accepts, for a one-time move, and a phrase names no machine any tool could match. Copying the phrase into the
item's body or replies would put words there that the item never said. The old file stays in git history whole.

**Also fixed in passing.** When the machine name was in backticks, today's warning carried a stray backtick; it no
longer does.

**Release and builds.** One build changes the warning, its description in the format's spec and its test cases,
in the next minor release. agent-cadence and ShiftLead print the warning as given, so neither needs a change.

**The rounds.** Two review rounds. Problems that would change the build, per design review: 2, then 0. The first
round found that one rule could drop text written before the machine name, and the stray backtick, both fixed.
The second tried the rule as code on every test line and found nothing that would change the build, so the
rounds end. The recommendation is Go.
