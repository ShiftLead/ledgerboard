# TD-095: the board's writer and the merge gate's verdicts

v3.0 makes the attention board a directory with one file per item (TD-070). TD-092 designed the item file, its id
and the reader, now built as B1 (TD-093) and being built as B2 (TD-094). This design covers the next two builds: B3,
the writer `board.py` over the directory, and B4, the merge gate's verdicts, which judge a PR that answers a board
item. The migration, the release and v3.0's removals (B5) are TD-098's, designed after this one.

**The writer (B3).**
- **Items are named by id.** Every edit (`snooze`, `due`, `done`, `decide`, `reply`) names its item by `--id`, and
  `--line`, `--expect` and `--under` go: an id cannot move, so there is nothing to guard against.
- **A close moves the file.** `done`, and a `decide` that closes, write the item's file under `archive/<YYYY-MM>/`
  and remove the open one in a single write. Nothing else moves or removes a file. A close whose archive path is
  already taken is refused.
- **The id.** `add` draws a random id and draws again while the name is held, open or archived, at most eight times
  before it refuses. A caller may pass its own `--id`, which is refused when held, so a service that retries an add
  sees *held* and knows it was written.
- **A write needs a v3 board.** `board.py` refuses to write a missing board, a directory with no `README.md`, a
  `README.md` declaring no `Ledgerboard:` line or a major other than 3, and a v2 board. It reads the README's own
  line, never a major a stub raises. It never creates a board: B5's `split` does that. `list` and `show` still read
  a v2 board.
- **`show`** prints the board for a person: each item that needs you, in its order, under a header naming its id
  and why it is shown, then with `--hidden` the hidden ones. Its bytes are exact, and the fixture runner gains a
  mode that compares printed text byte for byte.
- **Output names ids.** A write's JSON, `fmt`'s report, `list`'s lines and every refusal name the item's id where
  they named a line number.
- **`README.md` keeps the sweep's stamps.** Two sweeps that stamp the same board still conflict there. That is a
  known limit of v3.0, and moving stamps out is the consumers' choice later.

**The verdicts (B4).**
- **From the trees.** A verdict compares the base and head trees and reads which paths were added, removed or
  changed. A move counts the same whether the forge reports it as a rename or as two paths.
- **One item's change.** A lift passes only when the PR changes exactly one open item file in place, or removes it
  and adds that same id's archive file. Anything else goes to review. Whether the item should end open or closed
  is judged by comparing the head file byte for byte with what the decide edit writes.
- **A v2 board** at the base or the head goes to ordinary review, since no v3 writer writes one, and a split PR is
  among them.
- **Other repos' boards** reach the gate as read boards, not as text, matching the sweep from B2.
- **Renamed constants.** `BOARD_PATH` and `BOARD_ARCHIVE_PATH` become `BOARD_V2_PATH` and `BOARD_V2_ARCHIVE_PATH`,
  and `BOARD_DIR` names the directory. Each consumer's entry gets a line for this.

**Decided here rather than in B1.** B1's `done` collapses a why's whitespace but does not strip a final `.`, `?` or
`!`. So `board.py` collapses and then strips, in today's order, and B1 stays as built.

**Alternatives weighed.**
- **One plan for B3 to B5.** You chose to split the scope, so B5 is TD-098's.
- **Letting `board.py` create a missing board.** A typo in `--board` would then start a second board silently.
- **Judging a lift by the forge's file list.** Forges report a move differently, so the verdict would differ.

**How the rounds went.** Four rounds ran out of a cap of six. The design reviews raised 4, 4, 1 and then 0
build-changing findings, so the rounds ended by the stop rule. The start-of-round fact-checks raised 4, 3, 1 and 1.
One topic came back, the write gate's reading of `README.md`'s major (F278, F285, F286, F300, F307, F312). Each fix
refined the reader rather than undoing the last. Every finding was applied except F310, which was rejected
(F258 to F318; the record is `docs/reviews/TD-095.md`). The closing fact-check found one gap, the eight-draw
refusal's exit, now fixed. Round 4's fact-check fix F312 has not been read by a design review: the gate now runs its
own search for the README's `Ledgerboard:` line.
