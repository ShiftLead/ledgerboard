# TD-067: a lift of one part of a shared decide item

A `decide` item can ask one question about several entries: its Context names a parent and a gate, and its
`Parts:` lists the parts. When a person answers for one part alone, through the `set by=` route, the board half
of that route wrote `Decided:` on the whole item. The item then read as answered for every part, so the parts the
person had not answered dropped out of what they are asked, and the item read as an order to act on them.

**What changes.** `board.py decide --board-only` writes the item only when the answer closes it. While any entry
the item lists still carries the gate, it writes nothing, exits 0 and reports which entries are left
(`left_open`, also printed on stderr in every mode). The item stays open and unanswered, still asking the person
about the entries left. The part's answer is kept where it already was: its Log line, `gate lifted: … answer
"Go"; shared board item left open`. The same rule covers a board half run before the `set`, or by hand, while the
Context entry itself still carries the gate.

**The parts left** are answered as any unanswered item is. A later answer through `board.py decide` lifts each
entry still carrying the gate and logs the answered part as skipped. Since the item was never decided, that PR
can now be the answer's own review (the carve-out), where today's re-answer of a decided item always takes
ordinary review. A `set by=` on the last part closes the item with its `Decided:`, as today. The cost: until then
the item's text and `Parts:` still name the part already answered, since the line cannot mark it; a consumer
that reads the ledger can. A `--board-only` answer that only waits, or is a work order, writes as today.

**The merge gate.** The tripwire gains one flag, `tripwire-shared-decided`: a shared lift whose item gains a
`Decided:` while it stays open. It catches an older writer or a hand edit, and sends the PR to ordinary review.
v2.4 to v2.7 passed such a diff, so a consumer still vendoring an older `board.py` meets the flag once, on its
next shared lift; its review passes it, or the person re-answers.

**What it leaves alone.** No parse change, no new field, and no item key moves. `needs_you()`, `covers()`,
`closes()` and the sweep read as before. A shared item a cross-repo part sits in still closes on its last local
part, as cross-repo lifts do today. An event gate follows the same rule as a decision.

**Items already decided this way** read as before: `needs_you()` still classes them as a decided work order,
since the board alone cannot tell them apart. Each consumer repairs the ones it knows
with today's writers: close the item with `done`, then add a new `decide` asking about the entries left. The sweep
does not re-ask while the new item covers them. One edge: if the person answers the new item `Not yet` within 30
days of the old answer, the sweep files an `act` saying the old lift is owed, which the person closes.

**Options set aside.** Recording the answer per part on the line (a new field every reader must learn, and a copy
of the Log). Splitting the item into a new one for the parts left (a new item key, so a consumer's thread on the
item is lost). Refusing `--board-only` (it would break each wrapper's one commit).
