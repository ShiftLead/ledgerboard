# TD-098: the board's migration, the release and v3.0's removals

v3.0 makes the attention board a directory with one file per item (TD-070). TD-092 designed the item file and its
reader, built as B1 and B2; TD-095 designed the writer and the merge gate's verdicts, built as B3 and B4. This design
is the last build, B5: the split that turns a v2 board into a directory, what v3.0 removes, and the order in which
the repos move to it.

**The split (`board.py split`).**
- **One file per item.** The split reads the v2 board and its archive and writes the directory: each open item a
  file named by its id, each closed one under `archive/<YYYY-MM>/`. Every item gets the id that ShiftLead's old
  8-digit keys resolve to, so a persisted work order still finds its item.
- **`README.md`** is the board's text before its first item, with `Ledgerboard: 3` under its title and the heading
  that opened the items dropped. Relative links gain `../`, since the file moves one directory down. Lines after the
  first item that are no item (a `- (none)` placeholder, a note) are carried to its end, so nothing is lost. The
  byte rules (blank lines, a board with only a title or none) are exact and pinned by fixtures.
- **A stub stays at the old path.** It declares `Ledgerboard: 3` and points at the directory, so an old reader that
  checks the version refuses it rather than reading an empty board.
- **It refuses what it cannot split safely**: an undated item, two items with one id, a board already split or newer.
  It reads its own result back and refuses if the items differ. Everything else it splits, and it lists the README
  lines that may still describe the v2 board for you or the caller to keep or delete.

**What v3.0 removes.** The v2 text forms the module still reads and writes (the item line, its writers, the
old names) go in v3.0, which ships with TD-078's ledger half as one release. When it is cut is yours.

**The order (D12).**
- **Every repo bumps and splits in one PR.** agent-cadence vendors v3.0 and splits its own board in that PR;
  ShiftLead syncs it and splits its board in its sync PR, prepared while agent-cadence's is in review; this repo
  bumps its pin and splits. A roster repo does the same when TD-100 has it bump. A repo whose tools are v3.0 and
  whose board is still v2 would have no board writer, so no repo is left that way.
- **The cost.** A repo still on an old pin reads a split board as empty, so for a short time its sweep can file a
  duplicate item, closed by hand. You chose the **one-day rollout**: ShiftLead's and this repo's moves land by the
  end of the UTC day after agent-cadence's merges, so that is the window.
- **The PR that bumps and splits is judged by its head's pin**, so v3.0's cadence check judges it, and a split takes
  ordinary review.
- **The ledger's precondition** (v2.8's `migrate` finds nothing to change) is TD-078's, run in agent-cadence's and
  ShiftLead's PRs before they vendor.

**The consumers.** agent-cadence and ShiftLead each get an entry, filed through their own question seat once v3.0 is
cut. Each carries one rule: every place that reads a board as text or by line moves to the read board and the
item's id. Its done-when has two halves. A grep finds what still parses board text (the removed names, the regexes
that read a board, any `.text` or `.line` read on an item, any read of the board file's text). And because a grep
cannot see a caller that hands text on, each reader is run over the repo's own board before and after its split,
each held to what it prints: the daily nudge, its report and `list_sessions.py` show the same items, due dates and
sweep stamps; the cadence check's board row passes on both. Two runs can only be judged after the merge (the gate
sweep's dry run and the report's comparison with origin), so the session that merges records them, and the entry
closes only then. The plan lists the reads known today (for agent-cadence: `gate_sweep.py`, `ledger.py`,
`nudge_user_attention.py` with its sweep-stamp reader, `list_sessions.py`, `check_cadence.py`'s board row,
`check_claude_memory.sh`, the parity test, and what `adopt` seeds for a new repo); the entry finds the rest.

**What a new repo gets.** `adopt` seeds a v3 board: the directory's README and the stub at the old path, two fixed
files written together, never the README beside a kept v2 board. The parity test pins the stub to the module's
bytes. `adopt`'s own check reads a v2 board's text as today, but judges a v3 board through the module, so the
v3 version line and the README's prose lists do not make it refuse.

**Alternatives weighed.**
- **agent-cadence splitting in its own PR after ShiftLead's sync.** This was the plan until round 4. It left
  agent-cadence, where most sessions run, with no board writer until ShiftLead's sync merged, and bought no guarantee, since
  every other old-pin reader takes the same empty read.
- **Holding every split until the last roster repo bumps.** Each bumped repo would have no board writer until then.
- **A v2.x patch that refuses a stub.** It closes the gap but breaks the rule of no v2.x release after B1.

**How the rounds went.** Six rounds ran to the cap, and you bought a seventh (TD-105) and an eighth (TD-106). The
design reviews raised 3, 2, 2, 4, 2, 3, 3 and 0 build-changing findings; the start-of-round fact-checks 8, 1, 3, 1,
3, 1, 3 and 1. Two topics recurred:
- **The release order** came back in four rounds (F376, F393, F400, F401, F409, F420). Round 4's review judged the
  rollout wrong and it was redesigned as above; round 5's review judged it sound, and you chose the one-day rollout.
- **agent-cadence's code lines.** Rounds 5 to 7 each found reads in agent-cadence's scripts that the plan had not
  named (F442 to F480). Round 7 answered them with the rule and its two-part done-when above, so a read the list
  misses is caught in agent-cadence's own PR rather than by another design round.

Round 8's fact-check found one build-changing slip in round 7's seed fix (F485: `adopt`'s version check would have
refused every v3 board), and five minor ones. Its design review read every fix no review had read, judged each
right, and found nothing build-changing; it judged the rule and its done-when enough that further rounds need not
hunt agent-cadence's lines. Its six minor findings are applied. Every finding was applied except F425, which only
confirmed a fact (F351 to F496; the record is `docs/reviews/TD-098.md`).

**What you decide.** The board item asks Go, One more round or Hold. **Go** (my recommendation, since the last
design review raised nothing build-changing) files B5 `Part of` TD-070, with nothing blocking it (B3 and B4 are
merged), and drops the hold on TD-098. **One more round** runs a ninth round on round 8's minor fixes, then the
item comes again. **Hold** leaves B5 unfiled, with your note in TD-098's Ask.
