# TD-130: a board split keeps a paragraph below an item where the old reader read it

When a board in the old single-file form is split into one file per item, each item takes the indented lines right
under it, its detail block. Sometimes a session wrote an update a blank line below an item, such as *Update: moved
to next week. Due: next Monday.* The old format never counted that paragraph as the item's, since a detail block
ends at a blank line. Since TD-129, the split moves such a paragraph to the end of the board's README and warns
about it, so nothing is lost, but the update no longer sits beside its item.

**The choice.** The split does not attach it. The session running the split reads the warnings in its PR, and
where a paragraph is an item's update it moves it into that item's file by hand, as a bullet in its notes, a reply,
or a changed field such as its due date; a note about the board stays in the README. Nothing is built.

**Why.** The split writes exactly what the old reader read and checks itself against it; attaching would make it the
one reader that reads the paragraph differently. A paragraph after a blank line is sometimes an item's update and
sometimes a note about the next item or the section, and any rule that tells them apart would be a guess kept in the
format forever, for a one-time move. An item file's notes must be bullets with no blank line inside them, so the
paragraph could not even be attached as written without changing the new format. And an update that says *due next
Monday* beside the item's own due date needs a person or session to settle which is right; the warning puts that
where they can see both. A paragraph written right under an item with no blank line is already the item's, and the
split already keeps it there.

**Options set aside.** Attaching every indented paragraph up to the next item or heading; attaching only a paragraph
labelled *Update*; and attaching it and also applying its due date or context, an edit nobody made.

**The rounds.** One review round, which ran the split on test boards and found nothing that would change the
decision, so the rounds end. The recommendation is Go: the entry is archived and TD-129's warning stands.
