# TD-159: an answer that could not release an entry is refused when you press it

When an entry waits on your decision, your answer on a board question releases it. Two parts of the tool disagree
about which questions can do that. The part that writes your answer accepts two shapes that the check run before a
merge does not count: a question with extra words after the decision, and a question on a board that lists no people.
Today your press appears to work, the entry is released in the change, and only the merge check then says the release
is wrong, leaving a session to sort it out after you have already answered.

**The choice.** The answer writer refuses that press, before anything is written, and says what to do instead. The
problem moves from the merge check to the moment you press.

**What is refused.** Only an answer that would actually release an entry, on one of those two shapes. Words after the
decision are checked first, then the missing people list. Trailing full stops do not count as extra words.

**What still works.** "Not yet" and answers that ask for more work are still recorded, since they release nothing.
If the entry has already been released some other way, Go on the old question still closes it. Questions about
outside events and questions about another repo's entries are unchanged.

**What you do after a refusal.** For a question with extra words, answer the plain question the sweep files beside it.
The sweep does not file one if it asked within its re-ask window, 30 days by default, for example after you answered
"Not yet" or asked for more work. Until then, the session you drive can record the release as having no board item.
Once a plain question is open, that route is flagged, so the plain question has to be answered. For a board with no
people list, add the list, or use the same recorded release. The old question stays open after the entry is released,
and Go on it closes it.

**Limits.** Answers that have already landed are left alone. A change already open when this ships goes to ordinary
review with a different message, as it would have ended in review anyway. The wait of up to 30 days is accepted,
because shortening it would change when the sweep asks again about every entry.

**Options set aside.** Making the merge check accept both shapes, which would bring back a retired form and let anyone
answer on a board with no people list; recording these releases as having no board item, which would be untrue; warning
but writing anyway, which leaves the answer stuck; and refusing every answer on these questions, which would lose a
safe "Not yet".

**What it costs.** One small build with its spec text, code and test cases together, then a minor release, which may
be shared with the two builds from the earlier sweep design. No consumer is expected to change its code, and each
one's own tests check that when it takes the release.

**The rounds.** Three review rounds. The first found that you could be left with no question to answer after asking
for more work, that one proposed check guarded nothing real, and that the rule for extra words was not exact. The
second found that a question whose entry had already been released could no longer be closed. The third built the
plan and found nothing that would change the build. Its small points are fixed. The recommendation is Go, which
starts the build; one more round, or a hold with a note, are the alternatives.
