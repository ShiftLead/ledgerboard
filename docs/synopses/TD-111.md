# TD-111: a shared check for text a person reads

Paul switches between projects, so what a session leaves for him has to read cold: a question on the board, its
answers, a ledger entry's question, an entry's title. ShiftLead wrote down the rules on 2026-11-14 and asked for
one check that both agent-cadence and ShiftLead run, so the two do not each keep their own copy and drift apart.
This design puts that check in ledgerboard, the format library both of them already copy in.

**The rules.** A question or a task is one plain sentence of at most 25 words. It has no code in it: no file
name, folder path, function name, command option and so on. A question ends in a question mark. Every answer says
who acts: *I*, *you*, or someone else the writer's process knows, such as *a session*. A title is plain words,
with no code and no internal id. The longer background text may be any length; code in it gets a warning, never a
refusal.

**What stays out of ledgerboard.** ledgerboard may not know either tool that uses it. So the rules for what code
and a sentence look like are shared, and each tool supplies its own word lists. ledgerboard itself knows only
plain English words such as *I*, *you*, *we* and *nobody*. Each tool supplies the roles that act in its process
(*session*, *seat*, *techlead* and the rest), the terms its sessions made up (*slice*, *seam*), and the shapes of
its own ids (*B4*, *F12*, a pull request's *#123*). ledgerboard keeps only its own ledger ids (*TD-12*) as ids a
title may not hold.

Three other options were weighed and rejected. Keeping ShiftLead's words inside ledgerboard would refuse right
answers in any other process. Writing the words into each repo's files would copy one process's words into every
repo, where they would drift. Leaving the whole check to each tool is the drift this work exists to end. The two
tools still need one shared word list between them, or their lists can drift. That is theirs to settle: the
design asks them to, and does not choose for them.

**Who runs it.** Each tool runs the check when a session writes a question, answers or a title. A refusal lists
every problem, so the session can fix them all in one rewrite. ledgerboard's own internal writing steps never run
it, because bulk clean-up jobs write through them and must not be stopped by words no session just wrote. The
commands a person types into ledgerboard itself do not run it either: they hold no word lists, so they would
wrongly refuse *a session pins it*. Giving those commands options for the word lists was weighed and rejected for
that reason. ledgerboard's techlead agreed with this on 2026-11-14. The format text says exactly which writes are
checked, and which part of each is the question, the answers and the background.

**How a board item is read.** A board task must open with its task in bold, or it is refused. A board question
that opens in bold has the bold part read as the question, and the rest as background. So the bold part must be
the whole question: *Merge the PR* in bold followed by *now?* is refused, because the bold part has no question
mark. That is on purpose: the board shows the bold part as the item's headline, so it must stand as the question
alone, as ShiftLead's rules also read it. Reading the bold part and the rest together was weighed and rejected.
Leading spaces are ignored; a bold part that is only spaces counts as none, and the question is then read whole, a later bold part
included, with no refusal. A board question with no bold opening
is read whole, so a second sentence belongs in its details. Bold in the middle of a question (*Should I merge
**#42**?*) is refused, because the board would show that bold part, *#42*, as the headline: the session opens the
question with the bold part or drops the bold. So the headline and the question are always the same text. A
question in an item's details, on a question or a task, is checked the same way. Other board items (looks,
watches, notes) are not checked.

**How a ledger question is read.** Its first paragraph is the question and the rest is background, so a session
puts a blank line after the question. Most ledger questions written today are instructions, such as *Say Go to
file the one build, One more round, or Hold with a note*. Under this check a question must be one sentence that
ends in a question mark. The tools' templates for these questions change with it, and the design tells both tools
so. A retitled entry's new title is checked too.

**Known mistakes the check makes.** Some plain words look like code and are refused: *yes/no/maybe* and
*he/she/they* look like folder paths, *Node.js* like a file name, *iPhone* and *macOS* like code names. An id
shape a tool supplies may also catch a plain word, such as *P0* or *S3*. An abbreviation the check does not know,
such as *Ph.D.*, is wrongly counted as the end of a sentence; the common ones (*Dr.*, *p.m.*, *Nov.*) are known.
A person's name counts as who acts whatever its capitals, so on a board whose people include someone named Will,
*it will be built* passes.

The check also misses some things: "no code" means no code of the shapes it knows. A command written as plain
words (*git rebase*), a shell setting (*$HOME*), a one-letter command option (*-f*) and a file with no extension
(*Makefile*) pass, among others. A link's address and a bare web address are skipped. *Say no. Then what?* reads
as one sentence, because *no.* is read as an abbreviation (*No. 5*). *the US market* counts as naming who acts,
because *US* reads as *us*. Each problem line says how to fix the text, and each mistake found later is added to
the format's test cases.

A ledger id such as *TD-109* is allowed in a question, since ShiftLead's rules do not count an id as code, and is
refused only in a title. That is a choice, not an oversight: a question may point at the entry it is about, while
a title is what a person reads first.

**What changes from ShiftLead's version.** Besides the word lists each tool supplies, the design settles what
ShiftLead's text left open. It pins the exact wording of every problem line; one of ShiftLead's examples disagreed
with its own rule, and the rule wins. It pins how code is found when a web address sits inside it, and that a dash
or a slash alone is not a word. It adds contractions such as *we'll* that ShiftLead's list missed. It reads the
text after a bold task as background, where ShiftLead left it unread. ShiftLead's design text and one step of its
follow-up entry name word lists this design does not provide; amending those is ShiftLead's job.

**The release.** It ships as a small release that only adds. Paul cuts the release, as for every ledgerboard
release. The build does not wait for the release of TD-109's check (for a ledger question with no decision), which
has merged and is not yet released. When
the build merges, agent-cadence's techlead is told which release carries it. agent-cadence copies it in first,
then ShiftLead.

**Not done.** No old board or ledger is swept for these rules. ShiftLead's rules about questions passed up to Paul
and its **Not clear** button stay ShiftLead's. The check works only in Python.
