# TD-111: a shared check for text a person reads

Paul switches between projects, so what a session leaves for him — a question on the board, its answers, a
ledger entry's question, an entry's title — has to read cold. ShiftLead wrote down the rules on 2026-11-14 and
asked for one check that both agent-cadence and ShiftLead run, so the two do not each keep a copy that drifts. This
design puts that check in ledgerboard, the format library both of them already copy in.

**The rules.** A question or a task is one plain sentence of at most 25 words, with no code in it (no file name,
path, function name, option and so on), and a question ends in a question mark. Every answer says who acts: *I*,
*you*, or someone else the writer's process knows, such as *a session*. A title is plain words, with no code and
no internal label such as a ledger id or a finding number. The longer context may be any length, and code in it
gets a warning, never a refusal.

**What stays out of ledgerboard.** ledgerboard may not know either tool that uses it. ShiftLead's rules named its
own roles (*session*, *seat*, *techlead* and the rest) and its sessions' coined words (*slice*, *seam*). Here those
lists are handed in by whoever runs the check. ledgerboard itself knows only plain English: *I*, *you*, *we*,
*nobody* and the like. Where the two tools keep their shared list is their own choice; the design suggests one
list, agent-cadence's, so they cannot drift.

**Who runs it.** The tools' own writers run it when a session writes a question, answers or a title: a refusal
lists every problem, and the session rewrites and sends again. ledgerboard's own internal writing functions never
run it, because sweeps and migrations write through them and must not be stopped by words no session just wrote.
ledgerboard's own command lines do not run it either, since they have no list of who acts and would wrongly refuse
*a session pins it*. ledgerboard's techlead agreed with this on 2026-11-14. The format text says which writes a
writer should check.

**What changes from ShiftLead's version.** Besides the handed-in word lists, the design pins things ShiftLead's text
left open: what an answer of the form *Hold: <note>* is read by, the exact wording of every problem line (one
of ShiftLead's examples disagreed with its own rule, and the rule wins), and that the one-sentence test the
Queue's card uses leaves code out. ShiftLead's design text and one step of its follow-up entry name word lists
this design does not provide; amending those is ShiftLead's.

**The release.** A minor release: new functions, nothing existing changes. It waits on TD-109's build, whose
`set --ask` the new format text names. When the build merges, agent-cadence's techlead is told which release
carries it, so agent-cadence can copy it in, then ShiftLead.

**Not done.** No old board or ledger is swept for these rules; ShiftLead's rules about passed-up questions and its
**Not clear** button stay ShiftLead's.
