# TD-065: `Doer:`, who should do an act item's step

An `act` item on the board says a step someone must take, and nothing on its line says who. ShiftLead's **Have a
session do it** button hands that step to a session, and on 2026-11-11 Paul chose that the line itself names the
doer, so the press can go straight to that repo's or team's seat. The board's format is this repo's, so the field
has to land here first.

**The field.** An `act` line can carry `Doer: <repo>.` or `Doer: team <team>.`, right after its `Context:` and
before its `Due:`:

`- [ ] act 2026-11-12 (session `w-3`) — Rotate the deploy key. Context: TD-4. Doer: team ops. Due: 2026-11-14.`

A repo is named as the ledger already names repos. A team is named as a person is (letters, digits, `_`, `-`,
joined by dots), after the word `team`. A team is named alone, not with a repo: which repo a team works in is the
consumer's to resolve, and the format keeps no team list. A repo named `team` is `Doer: team.`, and a doer's repo never ends in a
dot, so the field's closing period is never part of the name. The module keeps the name as written and compares
none. A consumer that resolves one compares it ignoring case.

**Only on `act`.** The writer refuses a doer on any other kind (`decide`, `look`, `watch`, `fyi`, or no kind), and
the line check faults one there. A later release can widen this without changing how anything is read.

**Reading it.** Each item's record gains `doer`: its kind (`repo` or `team`), its name, and the value as it
stands. It is `null` when there is none or the value does not read. The reader is looser than the writer, as for
`Parts:`: odd spacing or a missing period still reads, and the line check names the fault. Nothing else reads the
field. What needs the person, the notes, the gate sweep and the merge gate's verdicts are unchanged.

**Writing it.** `board.py add --doer <value>` (and `item_line(doer=)`) takes the value exactly, neither trimmed nor
collapsed, so `"team "` is refused rather than becoming the repo `team`. `--doer` with `--decided` is refused. The
five edits keep the doer, and an edit that would change it is refused. No edit changes it: a step for another doer
is a new item. `fmt` never rewrites a misplaced or misspelled `Doer:`; it reports it.

**`Doer:` is now a field name everywhere `Parts:` is one.** A Context ends at it, and a reply cannot hold it.
`item_line()` refuses a text, context, answer, detail value or `--said` holding it. `decided_line()` cuts it from a
title or an answer option and refuses decision words that hold it. That bites anywhere a consumer files an item
from a ledger title or Ask that holds the words, as this entry's own title does: the consumer rephrases.

**The item key keeps the field.** So no key moves, and the release is a minor, **v2.8**, beside TD-067. It reads
one thing differently: a line written before v2.8 whose Context held the words `Doer: …` now reads a shorter
Context, and possibly a doer nobody meant. The line check cannot tell such a line from a new one. So, as with
`Parts:` in v2.3, each consumer's vendor PR shows that none of its boards holds one. A consumer acts on `doer` only
on a board whose writers all run v2.8. A v2.7 reader would read a new `Doer:` as part of the Context, so no
consumer writes one until every reader of its board runs v2.8.

**After the build.** One build, B1: the SPEC text, the code and the fixtures in one PR. Then a release (Paul's),
agent-cadence's vendor PR (its `board_edit.py add --doer`) and ShiftLead's TD-1661 pin bump.

**The rounds.** Four rounds, ended by the stop rule: the fourth design review found nothing that changes the build.
One topic kept coming back: how the grammar writes a doer's repo without a final dot. Rounds 1 to 3 each found the
grammar still accepted `acme..` or could not be tested (F5, F16, F23, F34, F36). It settles as a plain production,
`doer-part`, which round 4's design review read and passed. Unread by any design review are round 4's minor fixes
(F48–F55) and the closing fact-check's three corrections (F56–F58): when `reply` adds a period, when a reply ends the
value, and the round counts. The cap is six rounds, so a fifth is allowed.
