## TD-046: A new or changed `Waits` line is an error on the entry the edit changed, once every wait has a gate form

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-04
**Kind:** build
**Status:** Open
**Taken by:** 2e9dce7d0dea
**Blocked by:** TD-045, shiftlead#TD-1295
**Location:** ledgerboard/__init__.py (`check()`, `RETIRED_FIELDS`), SPEC.md *Retired words*, fixtures/

**Why:** v2.4 notes a `Waits` field only as ℹ `retired`, even on an entry the PR changed, so a session can still write a new `**Waits:** event — …` line, and does: no reader takes it as a gate, so the entry holds only while a consumer's own reader still honours it. Refusing it now would leave no legal way to write a host-witnessed wait (TD-045's `host-log` is not there yet). Once it is, every wait has a gate form, and a new or changed `Waits` line is a mistake the merge gate should stop, before v2.6's `migrate` and the retirement of `Waits`.

**Fix:** Once TD-045's `host-log` check is released, agent-cadence's reader runs on the hosts that should answer, and each consumer warns of a `host-log` gate no host has ever answered (TD-045's plan, *The builds*): `check()` grades the retired `Waits` field an error on an entry the edit changed (a line added or its text changed), naming the gate form to write (`until YYYY-MM-DD` or `event (<name>)` with its Event section), and keeps ℹ on a standing ledger, as the Log's and the events' flags are scoped. SPEC's *Retired words* says so; fixtures for an added, a changed and an untouched `Waits` line.

**Done when:** A PR that adds or changes a `Waits` line fails `check()` with the gate form to write, and a ledger whose untouched entries carry one still passes with ℹ.
