## TD-129: A board split moves text set below an item into the README, without a warning

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-16
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 984ade4b2266493886775a29cee2f62f

**Why:** On a v2 board, a session sometimes added a paragraph below an item after a blank line, indented, such as `**Update 2026-09-15:** … Due: 2026-09-22.`. The v2 line reader never counted it as the item's, and `split_board()` moves it into the new `README.md` with **no warning**. The item loses its update, and sometimes its real due date and context. The README then holds item text that nothing reads as an item.

This happened twice in the v3 moves of 2026-11-16:
- guardians-devenv (#34): an open item's update, `Context` and `Due` went into the README. A session found it by reading the README and repaired it with `board_edit.py due` and a ledger note.
- samscrape (#1138): 21 lines below a closed archive item went into the README. They are left in git, with the README naming where.

**Location:** ledgerboard/__init__.py (split_board_notes, _split_text, _split_readme); ledgerboard/board.py (plan_split)

**Fix:** The minimum build is the warning: `split_board_notes()` (`ledgerboard/__init__.py`, which `plan_split()` in `ledgerboard/board.py` calls) warns, naming the line, for every non-blank line between items, or after the last one, that `_split_text()`/`_split_readme()` carry into the README, so the session sees it before the split lands. Whether the split should also attach an indented paragraph that follows an item to that item's detail block is a design call: it changes what the item says, so it should be the person's to see.

**Done when:** A split of a board with an indented paragraph after a blank line below an item warns on that paragraph by line, with a fixture. If the design attaches it, the paragraph appears in the item's detail block.
