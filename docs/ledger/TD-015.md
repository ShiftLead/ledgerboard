## TD-015: ledgerboard ships one module file, so the writers both consumers need cannot live beside it

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-02
**Status:** Open
**Taken by:** 2e9dce7d0dea
**Part of:** TD-008
**Location:** ledgerboard (see Fix); SPEC.md; fixtures

**Why:** Under the target design (`docs/plans/target-design.md` §1.1) ledgerboard ships the file-level writers `ledger.py` and `board.py` beside the module. Both consumers already have files of those names, and ShiftLead imports the module as `sessionorc.ledgerboard`, so one byte-identical file set needs a package with relative imports.

**Fix:** Target design §1.1: move `ledgerboard.py` to `ledgerboard/__init__.py`, unchanged in role; `release.sh`, `fixtures/run.py` (`--module`, `--check-header`) and the tests load it as a package and check every file's release header; AGENTS.md and README state the amended boundary (SPEC, the module, the two file-level writers, fixtures; never git, the network, the roster, forges, sessions). The ADR amendment is ShiftLead's PR.

**Done when:** The package loads as a top-level package and as a subpackage (a test for each), every header check reads the package, AGENTS.md and README carry the new boundary, and the suite passes.
