## TD-071: The pinned agent-cadence writer writes Statuses this repo's v2.7 check rejects, until the pin moves

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-11
**Owner:** paul
**Status:** Open
**Taken by:** ao-ledgerboard-lb-grinder

**Why:** Found while building TD-063 (PR #221). From v2.7 (TD-058 B3), this repo's own `check()` makes a Status outside the closed set an error, and this repo's ledger is migrated to the closed set. Its ledger, though, is written through the agent-cadence this repo pins (`docs/cadence.toml`), whose vendored ledgerboard predates v2.7. Its `archive` still writes the old `Resolved YYYY-MM-DD: <why>` Status (TD-063's own archive did so), and its `new --location` still writes a header `Location`. The pinned `ledger.py --check` and the precheck pass both. Only this repo's module, `python3 -m ledgerboard.ledger --check --ledger docs/ledger`, sees the error. So each write through the pin can leave this ledger outside what this repo's own format says. TD-063 mended its archive by running `python3 -m ledgerboard.ledger migrate TD-063 --release 2.7` after it.

**Fix:** Move the pin to an agent-cadence that vendors v2.7, once v2.7 is released and agent-cadence's vendor PR has merged. The bump is Paul's (`agent-cadence bump` is outside every session's brief here). Until then, a session that archives or files through the pinned writer runs this repo's `migrate` on that entry afterwards (`python3 -m ledgerboard.ledger migrate TD-n --release 2.7`), and runs this repo's own `--check` before it asks for review.

**Done when:** The pin names an agent-cadence that vendors v2.7, and an `archive` through `agent-cadence run ledger.py` writes `Resolved YYYY-MM-DD` with its why in the Log.
