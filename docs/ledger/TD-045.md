## TD-045: The `host-log` check type: an event the host witnesses, so a wait no forge or file check can see still becomes a gate

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-04
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Taken by:** 2e9dce7d0dea
**Location:** SPEC.md *Events* (the check table), ledgerboard/__init__.py (`parse_check()`, `CHECK_TYPES`), fixtures/, docs/plans/target-design.md §4.2 and §7

**Why:** An event gate takes one of v2.4's three typed checks (`pr-merged`, `file-contains`, `ref-includes`). The target design (§4, its *Events are mechanical only* answer) sorts every open wait into three kinds: what a typed check sees, what the host already witnesses (a precheck failing again, a person's press, a session's message), and judgment, which is work blocked on by id. The second kind has no check type yet: §4.2's *Later: `host-log`* names it and leaves it for a later step, and its consumer half (the host's own event log and its query) is shiftlead#TD-1295.

Until it exists, a consumer cannot write such a wait as a gate. Its entries keep the retired `**Waits:** event — …` line, which `check()` only notes (ℹ `retired`) and which no reader takes as a gate. A consumer's live check waiting on "the next message of this kind from that team" is one today. When the consumer stops reading `Waits` as a hold (its v2.4 adoption) or v2.5 retires `Waits`, those entries lose their hold and become pickable before the event happens.

**Fix:** A format PR (spec, code and fixtures together), designed first and agreed before it is built (§2.4):
1. The check: `host-log <kind> "<text>" [times N]`, after §4.2's sketch. It states all four outcomes (passed, not yet, impossible, error) as the other types do; `since` is the date the gate was added (from the Log's `gate added`), so it is never written by hand, and a passed event stays passed.
2. Its confinement in `parse_check()`: `<kind>` a token of `[a-z0-9-]+` (the kinds are the host's vocabulary, never the package's: the package parses and confines, it never knows a host's kinds); the quoted text as `file-contains`'s; `N` a bounded positive integer.
3. `CHECK_TYPES` grows by one; `event-check` refuses a malformed one; fixtures for each refusal.
4. The release it ships in, and its place in §7's rollout beside shiftlead#TD-1295's build, so a consumer's wait moves from `Waits` to a gate before anything stops reading `Waits`.

**Done when:** `host-log` is in SPEC's check table with its four outcomes, `parse_check()` reads and confines it, fixtures hold each refusal, and it ships in a release.
