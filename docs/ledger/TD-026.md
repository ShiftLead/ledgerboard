## TD-026: A repo in an id, a Context ref or a pick is read three different ways, and today's regexes admit `../x` and non-ASCII

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-03
**Status:** Open
**Taken by:** 2e9dce7d0dea
**Blocked by:** TD-025
**Part of:** TD-010
**Location:** ledgerboard/__init__.py (XREPO_ITEM_RE, REF_TD_RE, new origin functions); SPEC.md; fixtures

**Why:** Each consumer derives a repo's key from its origin its own way, so two machines can pick different boards; and the cross-repo regexes accept traversal and non-ASCII names (target design §3.2, §4.1).

**Fix:** Per target design §3.2 and §4.1:
- `origin_key(url)` (host and full path, lowercased, `.git` and trailing `/` stripped, userinfo and port stripped; ssh, `ssh://` and https forms; none for `file://`, a plain path or a path failing the grammar) and `origin_path(url)` (its path part, lowercased);
- the `<repo>` grammar: `name` or `/`-separated components of ASCII `[A-Za-z0-9_.-]+`, none `.` or `..`, none starting with `-`; `XREPO_ITEM_RE` and `REF_TD_RE` tightened to it;
- `<repo>` compared case-insensitively in id lookups and Context-ref dedupe, while `item_key` stays byte-exact;
- resolvers prefer an exact path match to a suffix match (SPEC text for consumers).

**Done when:** Both functions and the tightened grammar are built with SPEC text and the §7.4 *Repos and origins* fixtures, and the suite passes.
