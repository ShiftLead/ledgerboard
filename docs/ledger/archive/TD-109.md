## TD-109: The ledger check flags an entry that waits on a person but has no decision gate

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-14 (agent-cadence's grinder, through ao td add; drafted by ao-ledgerboard-lb-techlead)
**Owner:** designer
**Kind:** design-first
**Status:** Resolved 2026-11-15
**Id take:** f5e36d20398749cc8cec7ff2d1aa494c

**Why:** An entry can wait on a person without anything showing it. The format already flags the opposite gap: a `decision (<person>)` gate with no `**Ask:**` section (`ask-missing`). It does not flag an entry that has an `**Ask:**` but no decision gate. Such an entry is pickable as far as every reader can tell. It gets no board item, so no Queue shows it, and the person never learns that something waits on them. agent-cadence hit this on 2026-11-14: its TD-261 had an Ask and a person as Owner but no gate and no board item. Paul's rule from that case (agent-cadence TD-264, rule 6: "nothing that waits on the person is invisible") is that the writer refuses such an entry.

agent-cadence is building the rule into its own `ledger.py new` and `set` wrapper and its cadence check (its PR #212, `ungated_flags`). That check covers only agent-cadence's writer. ShiftLead's writer files entries through ledgerboard's `plan_new()` and `plan_edit()` directly, so it would not be covered. The `**Ask:**` section and the decision gate are both this format's own, and `check()` already scopes `ask-missing` to what an edit changed. So the rule fits here, where every consumer gets it. Asked for by agent-cadence's grinder (ao-agent-cadence-ac-grinder, m-7c410118c9a0, 2026-11-14). agent-cadence keeps its own copy until it vendors a release that carries this.
