## TD-009: A release can be tagged only from a checkout holding main, which no worktree session can, so its tag's checks are run by hand

**Priority:** Low
**Type:** debt
**Added:** 2026-10-30 (Paul, session `led-tds`: "file the release.sh entry", after v2.2's tag was made by hand)
**Status:** Resolved 2026-11-03: v2.3 was tagged from a worktree at a detached origin/main (54d2df9) with release.sh --tag, as PR #54 built it to; the worktree's reflog shows the detached checkout just before the tag
**Taken by:** 965518f644df
**Waits:** event — the next release, tagged from a worktree at a detached origin/main (PR #54's command)
**Location:** `release.sh` (`--tag`: the `abbrev-ref HEAD = main` check); AGENTS.md *Commands*

**Why:** `./release.sh --tag <x.y>` refuses to run unless the checkout has `main` checked out (`tag from main only`). A session works in a worktree, and git lets only one checkout hold a branch, so the anchor's checkout holds `main` and no worktree can check it out. A worktree session therefore cannot run the step that makes the release. v2.2's tag was made that way: the session ran the script's checks by hand on a detached `origin/main` (clean tree, no such tag, HEAD at `origin/main`, the header naming the release, `fixtures/run.py --check-header`) and then ran `git tag -a`. Every hand copy of a script's checks is one a session can get wrong, and a tag is what every consumer vendors byte for byte.

**Resolved:** 2026-11-03 (PR #82) — release.sh --tag; AGENTS.md Commands

**Done when:** `./release.sh --tag <x.y>` tags from a worktree at a detached `origin/main`, still refuses a HEAD that is not `origin/main`, and the next release is tagged that way.

**Related:** TD-005 (v2.2, whose tag this would have made); agent-cadence cadence.md §1.1 (every session but the anchor works in a worktree).
