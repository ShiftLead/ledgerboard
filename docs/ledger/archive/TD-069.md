## TD-069: A detail block's Recommended reads its default's label twice when the caller's text already opens with it

**Priority:** Low
**Type:** debt
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-11
**Id take:** 92a863ea9697436db917025aafd1c76f

**Why:** On a `decide` with a default, the detail block's Recommended bullet opens with the default answer's label and ` — ` (`SPEC.md` *Edits*, the detail block; `_detail_lines()` in `ledgerboard/__init__.py`, which prefixes `label` and `CONSEQUENCE_SEP` to the `recommended` words). A caller that writes its `recommended` text starting with that label, which reads naturally, gets the label twice: `**Recommended:** Go — Go — …`. Nothing refuses or warns, and `board.py add --help` says only that `--detail` is "the detail block's parts, a JSON object", so a caller who has not read SPEC cannot know. No writer touches the block afterwards, so the doubled words stay in front of the person until the item closes.

Found by ShiftLead's session `ao-shiftlead-td-1551` (mail m-fe30ed35268f, 2026-11-11): a board item it added showed `**Recommended:** Go — Go — TD-1664 has drawn…`. It asked for `--help` to say the label is added, or for `add` to strip or refuse a leading `<label> —`, with a test.

**Location:** ledgerboard/__init__.py (item_line, _detail_lines, CONSEQUENCE_SEP); ledgerboard/board.py (add --detail help); SPEC.md (Edits, the detail block); fixtures/edit/, fixtures/board_writer/; tests/

**Resolved:** 2026-11-11 (PR #216)

**Done when:** `item_line()` and `board.py add` refuse a `recommended` that opens with the default's label and ` — `; `--help` and `SPEC.md` say the label is added; a fixture and a test cover it; the precheck green.
