**Priority:** Medium
**Type:** debt
**Added:** 2026-11-04
**Kind:** build
**Status:** Resolved 2026-11-06: check() errors on a new or changed Waits line (v2.7)
**Taken by:** 2e9dce7d0dea
**Blocked by:** TD-045, shiftlead#TD-1295
**Location:** ledgerboard/__init__.py (`check()`, `RETIRED_FIELDS`), SPEC.md *Retired words*, fixtures/

**Why:** v2.4 notes a `Waits` field only as ℹ `retired`, even on an entry the PR changed, so a session can still write a new `**Waits:** event — …` line, and does: no reader takes it as a gate, so the entry holds only while a consumer's own reader still honours it. Refusing it now would leave no legal way to write a host-witnessed wait (TD-045's `host-log` is not there yet). Once it is, every wait has a gate form, and a new or changed `Waits` line is a mistake the merge gate should stop, before v2.7's `migrate` and the retirement of `Waits`.

**Resolved:** 2026-11-06 (PR #189) — SPEC *Retired words*; fixtures/ledger_edit/check/waits_*
