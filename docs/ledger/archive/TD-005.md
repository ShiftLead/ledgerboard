## TD-005: Ledger entries get writers: a canonical form and `edit_entry`, as the board already has `edit_line`

**Priority:** Medium
**Added:** 2026-10-30 (Paul, session `sl-tds`: "ledgerboard is the right home"; the plan's eleven review rounds converged 2026-10-29)
**Status:** Resolved 2026-10-30: v2.2 released with the SPEC section, the writers, `Id take` and the fixtures
**Taken by:** b675de241e6c
**Location:** `ledgerboard.py` (new `canonical`, `entry_text`, `edit_entry`, `ENTRY_ACTIONS`; `check()`'s new kind; `CADENCE_FIELDS`); SPEC.md (a new *Ledger entries and their edits* section); `fixtures/ledger_edit/` (new) and `fixtures/run.py` `cases()`; README.md

**Why:** ledgerboard parses ledger entries but writes none. Its board writers (`item_line`, `edit_line`, `decided_line`) refuse an edit whose re-parse does not read back what was meant, and nothing does that for an entry. agent-cadence TD-173 makes every routine ledger write go through a helper and has its gate refuse an entry file the helper would not have written. That needs one canonical form and one writer, and both consumers vendor this module byte for byte, so the form belongs here: written in `ledger.py`, ShiftLead would need a second copy of it. Today `header_block()` also silently drops a header line that is not a field and keeps only the first of a repeated field, so a writer that rendered from the parse would lose text.
