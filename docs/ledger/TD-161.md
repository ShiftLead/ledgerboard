## TD-161: The merge gate cannot recognise a question the home tool asks the person

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-22 (agent-cadence's grinder, by request; drafted by lb-techlead)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** 4e9de1983cda4746aa19697a1fc47ad0

**Why:** ShiftLead's home now lands a PR that asks the person about one entry, squash-merged at once with no review (ShiftLead TD-2048, PR 4358, writer `_ask_in_tree` in `src/sessionorc/board.py`). Its subject is `<tool>: ask <person> on TD-n (session n/a)`. The merge gate has verdicts for the board's tool edits and for the ledger lift, but none for this write, so each one reads as landed without review in agent-cadence's weekly audit and hides a real unreviewed merge. No person's press stands behind the write, so a verdict has to prove from the trees that the change only holds an entry back and asks. agent-cadence TD-297 waits on this entry, then vendors the release and adds the review row.

**Location:** ledgerboard/__init__.py (LIFT_SUBJECT_RE, ledger_lift_verdict, sweep); SPEC.md (The merge gate's verdicts)

**Fix:** Design, then build, beside `LIFT_SUBJECT_RE` and `ledger_lift_verdict()`: a subject regex for the write, and a verdict over the PR's base and head trees that recomputes the write and never trusts the title. It passes only one commit that changes one open entry's file and adds one board item.

- **The entry:** `decision (<person>)` joins Blocked by with every earlier gate kept, no decision gate of any person's stands at the base, Ask, Context, Answers and Lifts are written, the Log gains exactly `gate added: decision (<person>)` and `asked by the stage record: <nonce>`, and nothing else changes.
- **The board:** exactly the `decide` item `sweep()` would file for that gate.

What the writer does, read from ShiftLead at 715dab451ea0 and run on an invented entry, which the design has to allow for:

- It replaces an earlier Ask and Answers rather than keeping them. Its first edit is still judged with the earlier Answers, so an entry whose earlier Answers cannot lift is refused before it is replaced.
- The canonical form reorders Blocked by (`until 2026-11-02` becomes `decision (ann), until 2026-11-02`), so gates are compared as a set, not as a suffix.
- It calls `sweep()` with `reask_days=0`, and with no `resolve`. A recomputation at the default window would file nothing after a recent answer.
- The item's id is a random draw and its Due is the writer's local today, while the Log's date is UTC. Neither can be compared byte for byte, so the design bounds the dates as `ledger_lift_verdict()` does.
- **Version skew, open for the design:** ShiftLead vendors v3.5, and v3.6's sweep adds a clause to the item's context when older open items name the entry. A verdict at v3.6 or later recomputing a v3.5 writer's item differs in exactly that case. The design says whether the verdict tolerates it, or the carve-out starts only once ShiftLead has synced.

Tests: ordinary review for the same title on a PR that also changes another field, another entry or another board item, drops an existing gate, or adds a gate to an entry already waiting on a decision.
