## TD-028: An entry waiting on something outside the ledger has no checkable condition, so the wait is invisible and never lifts by itself

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-03
**Status:** Open
**Taken by:** 2e9dce7d0dea
**Blocked by:** TD-027
**Part of:** TD-010
**Location:** ledgerboard/__init__.py (event sections, check); SPEC.md Events, Appendix: grammar; fixtures/ledger

**Why:** Waits on a merge, a vendored release or a deploy are prose today (`Waits:`, a Status note), so nothing can tell when they end (target design §4).

**Fix:** Per target design §4.1, §4.2 and §4.4's format half:
- the `**Event (<name>):**` section: a plain-words line, then exactly one `check:` line naming a typed check; required for each `event (<name>)` gate;
- the three check types and their argument shapes: `pr-merged <repo>#<n>`, `file-contains <repo>[@<ref>] <path> "<text>"`, `ref-includes <repo>@<ref> <commit>`, with each type's four outcomes stated in SPEC (passed, not yet, impossible, error);
- argument confinement in `check()`: the `<repo>` grammar, `n`, `commit`, `ref` and `path` refusals, text quoted to the line's last `"`, matched literally;
- `check()` notes (ℹ) an Event section with no gate unless a `gate lifted: event (<name>)` Log line explains it; a re-added gate reuses the section;
- SPEC's grammar appendix adds Event sections.

**Done when:** Event sections and the three check types are built with SPEC text and fixtures (each confinement refusal, quoted text holding quotes), and the suite passes.
