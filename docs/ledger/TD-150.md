## TD-150: The gate sweep asks a decision while another blocker of its entry is still open

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-18 (agent-cadence's grinder, through an entry request; drafted by ao-ledgerboard-lb-techlead)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** a5ac858a3d4c43909dcdacb469063ca7

**Why:** `sweep()` files a `decide` item for an open entry's `decision (<p>)` gate whatever else its **Blocked by** names, so it asks a question that cannot be answered yet while another blocker is still open. agent-cadence's TD-291 makes that case common: after the person answers `One more round` on a design's end-of-rounds item, the design is held as `**Blocked by:** TD-<round>, decision (<person>)` while the bought round runs. The closed item's answer (`One more round`, which lifts nothing) keeps the gate quiet only for `reask_days` (30); once that passes, the sweep files the design's decide again mid-round, and a `Go` pressed on it lifts the design and its builds before the round's reviews have read the fixes the round was bought for. Checked on main: the `decision` branch of `sweep()` checks for a covering item, a recent answer without a lift, a `kept waiting` Log line and an answer owing a lift, and never the gate's other items; SPEC *The gate sweep* (the `decision (<p>)` bullet) lists the same four conditions. Asked for by agent-cadence's grinder for its TD-291, whose cadence.md §4.8 writes the hold.

**Location:** ledgerboard/__init__.py (sweep, the decision branch); SPEC.md (The gate sweep, the decision bullet)

**Fix:** Settle the rule, then build it with SPEC text, fixtures and a test in one PR (a minor release, since the sweep files less). The asker's shape: the sweep files no item for a `decision (<p>)` gate while the entry's **Blocked by** also names an open entry, an id the ledger holds open, so the question is asked when it can be answered. Open for the design: whether a `<repo>#TD-n` blocker counts (the module reads no other repo, so it needs the resolver `pickable()` takes, or counts only this ledger's ids); whether an archived or unknown id counts as open; whether the sweep closes an open decide item for the gate once a new blocker is added, or only defers filing one; whether an entry's parent being blocked counts (a `Parts:` item); and whether `check()`'s `decision-uncovered` refusal, which wants a decide item for a newly gained `decision (<p>)`, holds the same way.

**Done when:** One PR has merged with the SPEC text, a fixture or test showing a `decision (<p>)` gate next to an open entry's id filing nothing past `reask_days` and filing once that entry is archived, and the suite, the fixtures and ruff green.
