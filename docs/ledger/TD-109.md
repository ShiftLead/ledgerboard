## TD-109: The ledger check flags an entry that waits on a person but has no decision gate

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-14 (agent-cadence's grinder, through ao td add; drafted by ao-ledgerboard-lb-techlead)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** f5e36d20398749cc8cec7ff2d1aa494c

**Why:** An entry can wait on a person without anything showing it. The format already flags the opposite gap: a `decision (<person>)` gate with no `**Ask:**` section (`ask-missing`). It does not flag an entry that has an `**Ask:**` but no decision gate. Such an entry is pickable as far as every reader can tell. It gets no board item, so no Queue shows it, and the person never learns that something waits on them. agent-cadence hit this on 2026-11-14: its TD-261 had an Ask and a person as Owner but no gate and no board item. Paul's rule from that case (agent-cadence TD-264, rule 6: "nothing that waits on the person is invisible") is that the writer refuses such an entry.

agent-cadence is building the rule into its own `ledger.py new` and `set` wrapper and its cadence check (its PR #212, `ungated_flags`). That check covers only agent-cadence's writer. ShiftLead's writer files entries through ledgerboard's `plan_new()` and `plan_edit()` directly, so it would not be covered. The `**Ask:**` section and the decision gate are both this format's own, and `check()` already scopes `ask-missing` to what an edit changed. So the rule fits here, where every consumer gets it. Asked for by agent-cadence's grinder (ao-agent-cadence-ac-grinder, m-7c410118c9a0, 2026-11-14). agent-cadence keeps its own copy until it vendors a release that carries this.

**Design PR:** #330

**Location:** SPEC.md (The ledger: Blocked by, decision gates and ask-missing; Versions); ledgerboard/__init__.py (check(), EDIT_ERRORS, TEXT_KINDS); ledgerboard/ledger.py (plan_new(), plan_edit()); fixtures/ledger/, fixtures/ledger_edit/

**Fix:** Design the rule as a `check()` flag that pairs with `ask-missing`. Working name: `decision-missing`. It is an error on an entry the edit changed, and ℹ on a standing ledger. `plan_new()` and `plan_edit()` then refuse what it refuses. The design settles these questions:

1. **The Ask half.** An open entry with an `**Ask:**` section and no `decision (<person>)` gate is flagged. Settle what counts as standing. agent-cadence's reading is that an entry the base already had in this shape, or whose base carried a decision gate the edit lifts, is standing: only the person drops a decision, so a lift that leaves the Ask is their answer, and `SPEC.md` *Events* ("Lifting is text") keeps an answered Ask in the entry. Check that this reading holds for a decision lifted by a board answer.
2. **The Owner half.** `Owner` is not one of the format's fields: a ledger declares it on its `Fields:` line. So the format cannot tell which Owner values name a person. Either the caller passes the person words in (as `pickable()` takes a resolver), or a ledger declares them (for example, a `Fields:` vocabulary mark). Or this half stays each consumer's. Agree the choice with agent-cadence, whose rule counts `person`, or a name that some decision gate names.
3. **Its release.** A new error on a changed entry tightens the check but does not change the canonical entry form. Confirm it is a minor release under SPEC *Versions*, and say what a consumer's existing open entries need before they vendor it. agent-cadence had six such entries on 2026-11-14.

Write the plan in `docs/plans/`, then the build (SPEC text, code and fixtures together). Tell agent-cadence's techlead the release, so that its TD-264 calls this check rather than keeping its own copy.

**Done when:** A release of ledgerboard flags an open entry that waits on a person with no decision gate. The Ask half is always flagged. The Owner half is flagged as the design decides, or the design records why it stays each consumer's. The flag is an error on an entry an edit changed and ℹ on a standing ledger, `plan_new()` and `plan_edit()` refuse it, and fixtures hold each case. agent-cadence has been told which release carries it.
