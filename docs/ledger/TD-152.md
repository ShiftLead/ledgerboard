## TD-152: The gate sweep asks again when an open item already names the entry, and the person's answer there then cannot lift the gate

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-21 (samscrape's session, through an entry request; drafted by ao-ledgerboard-lb-techlead)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** 67107546dafc4e28906d3a69e4d3394c

**Why:** The gate sweep asks the person a second time when an open board item already asks about the entry in a form `covers()` does not read, and the merge gate then cannot count the person's answer on the first item. `covers()` finds an item only when its Context names the entry and its gate and nothing else (`_context_gate()` returns no entry when the Context names more than one, and no gate when it names none), so an item whose Context lists several entries, or names an entry with no gate, is invisible to the sweep, which files a second `decide` with Context `TD-n decision (<p>)`. The person answers whichever item they see first; when that is the first one, the tripwire flags the lift (`tripwire-no-decided`: no item covering it gains a `Decided:`), and logging the lift with `; no board item` instead is flagged too (`tripwire-no-board-item`: an open item asks it), so the lift cannot land as the person answered it. Neither message names the item it means, so finding the second item took a search by hand. Checked on main: `_context_gate()` and `covers()` (SPEC *The gate sweep*) read only a one-entry, one-gate Context; the two tripwire messages in `tripwire()` name the entry and the gate, never an item. Reported by samscrape's session (2026-11-21, its TD-259): an open `act` item added 2026-08-16 with Context `TD-259, TD-257, TD-369`, a second `decide` filed by the sweep on 2026-11-16, the first answered `done`.

**Location:** ledgerboard/__init__.py (_context_gate, covers, sweep, tripwire); SPEC.md (The gate sweep, The merge gate's verdicts, The board writer)

**Fix:** Three asks from the report, the first two plain and the third a shape to design:
1. Before filing a `decide` for an uncovered `decision (<p>)`, the sweep looks for any open item on the person's board whose Context mentions the entry (with no gate, or among other entries) and, rather than file a duplicate, links to it or warns. What it then does (file nothing, file with a pointer, or report the near-miss to the host) is the design's to settle, with how such an item's answer may lift the gate.
2. The tripwire's `tripwire-no-decided` and `tripwire-no-board-item` messages name the ids of the items they mean (the open item that asks it; the items covering it), so a person or session can act on them without a search.
3. Consider letting an answer on an item that names several entries say which entry's gate it lifts (for example a lift naming the entry on the board writer's decide), so the person's actual answer counts toward the lift. This touches the board writer and the merge gate's verdicts, and a consumer's front end (agent-cadence's `board_edit.py decide`) would take it in its vendor PR.
A design round settles 1 and 3; 2 may ship as its own build.
