## TD-152: The gate sweep asks again when an open item already names the entry, and the person's answer there then cannot lift the gate

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-21 (samscrape's session, through an entry request; drafted by ao-ledgerboard-lb-techlead)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** 67107546dafc4e28906d3a69e4d3394c
**Blocked by:** decision (paul)

**Why:** The gate sweep asks the person a second time when an open board item already asks about the entry in a form `covers()` does not read, and the merge gate then cannot count the person's answer on the first item. `covers()` finds an item only when it is a `decide` item, on a board whose `People:` lists the gate's person, whose Context names the entry (or its parent, with the entry among its `Parts:`) and the gate with nothing after it; `_context_gate()` returns no entry when the Context names more than one, and no gate when it names none. So an `act` item about the entry, or a `decide` whose Context lists several entries or names no gate, is invisible to the sweep, which files a second `decide` with Context `TD-n decision (<p>)`. The person answers whichever item they see first; when that is the first one, the tripwire flags the lift (`tripwire-no-decided`: no item covering it gains a `Decided:`), and logging the lift with `; no board item` instead is flagged too (`tripwire-no-board-item`: an open item covering it asks it), so the lift cannot land as the person answered it. Neither message names the item it means, so finding the second item took a search by hand. Checked on main: `_covers()`, `_context_gate()` and `_sweep_item()` as above (SPEC *The gate sweep*); the two tripwire messages in `tripwire()` name the entry and the gate, never an item. Reported by samscrape's session on 2026-11-21: an older open `act` item naming the entry among two others and no gate, a second `decide` filed by the sweep, and the person's answer on the first.

**Context:** One more round: a session runs a seventh review round, past this design's cap of six, on round 6's fixes, among them the lettered test cases, which no design reviewer has read, then asks again.
