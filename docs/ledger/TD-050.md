## TD-050: `board.py add` and `item_line()` write a `decide`'s `Parts:` (the writer SPEC leaves to v2.4)

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-04 (agent-cadence's grinder, through `ao td add` for agent-cadence TD-221; drafted by ao-ledgerboard-lb-techlead)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Taken by:** ao-ledgerboard-lb-techlead
**Location:** ledgerboard/__init__.py (`item_line`, `item_problem`), ledgerboard/board.py (`TAKES["add"]`, the `add` plan and its argument parser), SPEC.md *The board* (`Parts:`) and *The board writer*, docs/plans/target-design.md §6 and §7's release table (v2.3/v2.4 rows), fixtures/board_writer, fixtures/edit

**Why:** `Parts:` has been read, ordered and keyed since v2.3, and SPEC says "what an answer does to the parts it lists is v2.4's, and so is its writer". The target design's v2.3 row says the same: "the writer that fills it and checks the parts' gates comes in v2.4". v2.4 shipped `covers()`, `decide_lift()` and `closes()`, which all read `Parts:`. It shipped no writer: `item_line()` takes no `parts=`, and `board.py add` has no `parts` in `TAKES["add"]`. A design's end-of-rounds item is meant to hold all its builds at once: one `decide` on the parent, with the builds in `Parts:`, which `covers()` counts as covering each build's gate. Without a writer, a consumer's sweep files one `Go | Not yet` item per held build beside it. The consumers then have no `Parts:` to show either: agent-cadence's `board_edit.py` passes `add` through, and ShiftLead's Queue (its TD-1378) shows the board. Asked for by agent-cadence TD-221.

**Fix:** A design round settles the shape, then a build writes it. Proposed: `item_line(parts=[ids])` writes ` Parts: TD-a, TD-b.` right after the Context, as SPEC's order says; it refuses it on any kind but `decide`, an id twice, or a Context that does not name exactly one entry; and `item_problem()` faults the same. `board.py add --parts TD-a,TD-b` passes it through, so a consumer's `add` passthrough needs no code of its own. Open for the design: how "checks the parts' gates" is met when `add` reads no ledger today (an optional `--ledger` whose entries' `Part of` must name the Context entry and still carry its gate, as `decide_lift` refuses at answer time, or no check at write time); and whether this is a v2.4 patch or v2.5. Done when: `board.py add --parts` writes the field and refuses it on a non-`decide` kind; fixtures show the line written and refused, and `covers()` reading each listed part as covered by the parent's item; and SPEC names the writer.
