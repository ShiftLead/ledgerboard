## TD-128: A board split keeps only the first word of an item's host, so a host written as a phrase is cut

**Priority:** Low
**Type:** debt
**Added:** 2026-11-16
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** 0d8851bb79a345f4a1ca6b16af2768d8

**Why:** `split_board()` keeps only the first word of a v2 item's host, so a host written as a phrase is cut in the item file's `Session` field. A v2 line `- [ ] 2026-09-14 (session b8a7317c on Pat's laptop, main) — …` splits to `**Session:** b8a7317c on Pat's`, and the split warns `head text not carried: laptop, main`. A host with no apostrophe (`on pats laptop`) is cut the same way. The cause is `HEAD_HOST_RE` (`\bon\s+`?([^\s`,;)]+)`), which reads the host as one non-space token, as the format line's `<host>` (`hostname -s`) intends. The warning makes the cut look like ordinary head text (a branch) was dropped, when part of the host itself was. Found in the v3 moves of 2026-11-16: seven of contractmatch's archived items, whose heads named a host as a phrase (`on <name>'s WSL2 devcontainer`), now read `on <name>'s` (contractmatch#260's review).

**Ask:** Should the board split's clearer warning for a machine name written as a phrase be built now, two review rounds having ended it?

Go: a session files its one build, and the grinders build it. One more round: a session runs a third review round on round 2's small fixes, then asks again. Hold with a note: nothing is built, and a session revises the design as the note says.
