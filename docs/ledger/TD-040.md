## TD-040: Fixtures do not name the release they apply to, so a consumer cannot run the set for its own pin

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-04
**Kind:** design-first
**Status:** Open
**Taken by:** ao-ledgerboard-lb-grinder
**Location:** fixtures/ (every case); fixtures/run.py; SPEC.md (if the fixtures' form is stated there)

**Why:** Target design §7.4's last bullet: "Fixtures carry the release they apply to, so a consumer can run the set for its own pin (CommonMark publishes its tests per spec version)." Nothing spells how: SPEC, the design and `fixtures/run.py` name no field, file or option for it. TD-035 carried it as one bullet of its Fix. On 2026-11-04 Paul answered the steer that asked for its shape (m-8dbfc6bf991c; his reply m-537d6a2b218f) by splitting it off, so it is designed here before anything is built.

**Fix:** Open in the design round: how a case names its release (a per-case key such as `"release": "<x.y>"` in each `cases.json` case and directory case's `cmd.json`, a file per directory, or a directory per release), whether it names the release that added the case or the one that last changed its expected output, how `fixtures/run.py` runs the set for a pin (e.g. `--release <x.y>`, the cases at or below it), and how the existing untagged cases get their release. Then the builds it files, SPEC/run.py docs and fixtures together.

**Done when:** The shape is decided and its builds are filed, each naming this entry in `Part of:`.
