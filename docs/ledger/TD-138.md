## TD-138: The merge gate's check crashes on an answered card that names a gate but not one entry

**Priority:** High
**Type:** debt
**Added:** 2026-11-17
**Owner:** grinder
**Status:** Open
**Id take:** aead3e0d91794792b0f67891e5a047c6

**Why:** The merge gate's verdict for a PR that answers a board item and lifts its gate crashes on an item whose Context names a gate but not one single entry (two `TD-n` refs, for example `TD-8 and TD-9 decision (robin)`): `_item_gate()` returns no ref and a gate, the verdict passes its `gate is None` test, and then tests `"#" in ref` on None (`TypeError: argument of type 'NoneType' is not iterable`). TD-132's round 5 review reproduced it on a board-only answer of such an item. A verdict must never raise: the PR should go to ordinary review.

**Location:** ledgerboard/__init__.py (lift_pr_verdict); fixtures/verdict/

**Fix:** In `lift_pr_verdict()` (`ledgerboard/__init__.py`), treat an item whose `_item_gate()` returns no ref as the existing `lift-no-gate` review (its message already says *a decide whose Context names one entry and one gate*): test `ref is None` beside `gate is None`. Add a `fixtures/verdict/` case: an invented item whose Context names two entries and one gate, answered board-only, expecting `lift-no-gate`. No SPEC change: SPEC already says such an item is not one the verdict carves out.

**Done when:** `lift_pr_verdict()` returns `lift-no-gate` for an item whose Context names a gate but no single entry, the new verdict fixture passes, and the suite, fixtures and ruff are green.
