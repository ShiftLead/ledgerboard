## TD-057: The item writers' refusal of a field's name in a text does not say which name matched

**Priority:** Low
**Type:** debt
**Added:** 2026-11-06 (requested by ao-agent-cadence-ac-techlead through ao td add; drafted by ao-ledgerboard-lb-techlead)
**Status:** Open
**Taken by:** ao-ledgerboard-lb-techlead
**Location:** ledgerboard/__init__.py (`_item_words`, `WRITER_FIELD_RE`; the decide-answer and reply refusals on `FIELD_NAME_RE`), fixtures/board_writer/add_refused_field/expected.json, fixtures/edit/expected.json, tests/ (new cases)

**Why:** The item writers refuse a text that carries a field's name without saying which name matched, so the caller has to find the word by trial. `_item_words` serves the detail block's parts, its `otherwise` and nested bullets, an answer, a board line's text and the context. It answers with all eight names: "may not carry Context:, Parts:, Due:, Hide until:, Answers:, Lifts:, Decided: or Closed:". Two other refusals have the same fault and list seven names: a decision's answer (`FIELD_NAME_RE` in the decide path) and a reply (`FIELD_NAME_RE` in `edit_line`'s reply action). The reader-side check `item_problem`, which `edit_line` also reaches, already names the field it found ("text: names a field (Due:)", fixtures/edit). Agent-cadence's techlead reported this on 2026-11-06, from Paul's trial review of three ShiftLead seats' transcripts (2026-11-03 to 2026-11-06). In those transcripts `board_edit` refused a detail or context text carrying `Context:`, `Due:` or `Decided:` three times, and each seat reworded it by trial.

**Fix:** Make each of the three refusals name the first field name it matched, quoted as it is written in the text (`due:` stays `due:`), and the part it was found in, as `item_problem` already does. Update the cases that pin the old wording in the same PR:
- `fixtures/board_writer/add_refused_field/expected.json`
- `fixtures/edit/expected.json`, the `_item_words` cases (a board line's text twice, the context, the detail block's caveats), the decision-answer case and the four reply cases

This changes only the refusals' words, not the format. SPEC.md does not quote them.

The report also suggested a way to write such a word: for example, backticks that the reader then skips. Today no field reader skips a code span, so that would change how the reader reads a line. That is a format change (SPEC, a version note), so it is not part of this entry. If it is wanted, it is a design-first entry of its own.

**Done when:** Each of the three refusals names the first field name it matched, as written, and the part it was in. The updated cases pin this for the detail block, the context, a decision's answer and a reply. A new case pins it for an answer through `_item_words`, and another for a lower-case `due:`. The precheck is green (`ruff check .`, `python3 -m unittest discover -s tests`, `python3 fixtures/run.py`).
