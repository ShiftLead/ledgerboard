## TD-004: A release names the vendoring tool agent-cadence, not dev-cadence

**Priority:** Low
**Added:** 2026-10-29 (Paul, session `dc-tds`)
**Status:** Open 2026-10-30: the text built on main (line 2, the docstring, README, AGENTS.md); done when both consumers vendor v2.2. Not part of agent-cadence's rename sitting: until this ships, agent-cadence's `tests/one_name_allow.txt` keeps its vendored `ledgerboard.py` whole. 2026-10-30: released in v2.2 (PR #37, tag v2.2); open until agent-cadence and ShiftLead vendor it
**Location:** `ledgerboard.py` lines 2 and 14 (the SYNCED FILE line and the docstring's *two consumers*); README.md lines 14–20; AGENTS.md (the session-start line, the pin prose, the vendoring notes); the seeded skills; `docs/cadence.toml` comments

**Why:** dev-cadence is moving to `ShiftLead/agent-cadence` and the tool is renamed with it (agent-cadence's plan *2026-10-29-hard-rename*). The module's text is byte-frozen in every vendored copy: agent-cadence's `tests/ledgerboard/run.py --check-header` hashes every byte after line 1, and ShiftLead holds its copy byte-equal to the pinned tree's. So the name in `ledgerboard.py` changes only with a release, and that release is outside the sitting. The repo's own pin, settings line and skills move in the sitting's C5 PR. This entry covers only the release text.

**Fix:** a release (v2.2) whose line 2 reads *vendored by agent-cadence as files/scripts/ledgerboard.py* and whose docstring names agent-cadence; README and AGENTS.md follow. Then `vendor_ledgerboard.sh` in an agent-cadence PR (which drops `ledgerboard.py` and `tests/ledgerboard/**` from `one_name_allow.txt`), and ShiftLead's re-vendor. Done when both consumers vendor the release.
