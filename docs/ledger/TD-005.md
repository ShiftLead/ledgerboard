## TD-005: Ledger entries get writers: a canonical form and `edit_entry`, as the board already has `edit_line`

**Priority:** Medium

**Status:** Open 2026-10-30: ships in one sitting with TD-004, TD-006 and agent-cadence TD-188 step 1 (`Id take`), as v2.2; the sitting's order and what is merged are in *The v2.2 sitting* below.
**Taken by:** b675de241e6c
**Location:** `ledgerboard.py` (new `canonical`, `entry_text`, `edit_entry`, `ENTRY_ACTIONS`; `check()`'s new kind; `CADENCE_FIELDS`); SPEC.md (a new *Ledger entries and their edits* section); `fixtures/ledger_edit/` (new) and `fixtures/run.py` `cases()`; README.md

**Why:** ledgerboard parses ledger entries but writes none. Its board writers (`item_line`, `edit_line`, `decided_line`) refuse an edit whose re-parse does not read back what was meant, and nothing does that for an entry. agent-cadence TD-173 makes every routine ledger write go through a helper and has its gate refuse an entry file the helper would not have written. That needs one canonical form and one writer, and both consumers vendor this module byte for byte, so the form belongs here: written in `ledger.py`, ShiftLead would need a second copy of it. Today `header_block()` also silently drops a header line that is not a field and keeps only the first of a repeated field, so a writer that rendered from the parse would lose text.

**Fix:** v2.2, a minor release: it reads everything v2.x wrote, and v2.1 reads what it writes. The full design and the rounds' reasons are agent-cadence's plan `docs/plans/2026-10-29-ledger-writer-in-ledgerboard.md`.
- **SPEC, *Ledger entries and their edits*:**
  - The header block is the lines after the heading, up to the first blank line. Every line in it is a `**Name:** value` field, and a name appears once.
  - The body is *sections*. A section's *lead* is the bold opening of its first paragraph (`**Name**` or `**Name:**`). A section runs through every following paragraph up to the next bold-led one, so a Fix keeps its bullets. Names match by `field_key`, colon optional (`Done when` with or without one). A qualified lead (`**Fix (to design):**`, a dated `**Note (…):**`) is its own section, matched only by its whole text. A body lead named like a field (`**Location:**` in a body) is a body section, never a field. Text before the first bold lead is an unnamed section, kept verbatim.
  - Canonical form: the heading, a blank line, the header in the order `Priority, Type, Added, Owner, Kind, Status, Taken by, Id take, Blocked by, Waits, Part of, Location`, then any other field in the order the file had it, a blank line, then the body byte for byte with `\n` endings and one trailing newline. Line endings are normalised first. `Owner`, `Kind`, `Taken by` and `Waits` are placed by this order, not declared as cadence fields. `Resolved` is not in the order; a header `Resolved` is kept as found by `canonical()`.
  - The archived entry: Status `Resolved YYYY-MM-DD: why` with Fix replaced by `**Resolved:** YYYY-MM-DD (PR #n) — <pointer>`, or `Superseded YYYY-MM-DD by TD-n: why` with Why and Fix kept.
  - A change to the canonical form is a minor release.
- **`Id take`** joins `CADENCE_FIELDS` and SPEC (agent-cadence TD-188 step 1), so the order does not change again later.
- **`canonical(text)`:** presumes an entry with exactly one `## TD-n:` heading (what `v2_problems()` requires of its file, matched against the name by the caller) and refuses any other text. It renders from the raw header lines: the twelve ordered fields spelled as SPEC lists them, others as the file spells them, so it is idempotent. **Refused** when the header block holds a line that is not a field, a repeated field, or a field below the header that `entries()` would lift; rendering would lose or duplicate those lines, so a person fixes them. Refusal rule: body text and header dict unchanged, or refused.
- **`entry_text(id, title, fields, sections)`:** a new entry in canonical form.
- **`edit_entry(text, action, *, today, …)`** with `ENTRY_ACTIONS`, mirroring `edit_line`/`EDIT_ACTIONS`. Each action's keyword arguments are what its bullet below names (for `archive`: `why`, `pr`, `pointer`, `as_is`, `superseded_by`; the pointer is the doc, test or code that now carries the lasting content). Each action is refused unless its re-parse reads back exactly the intended change and nothing else, and every action returns canonical form; an entry `canonical()` refuses is refused the same way.
  - `set`: set or remove fields (an empty value removes).
  - `note`: append ` YYYY-MM-DD: words` to Status; refused if Status's first word would change or `words` holds a newline. With no Status it writes `**Status:** YYYY-MM-DD: words`.
  - `edit`: replace one named section's paragraphs. A section the body lacks is added after the first Why, else before the first of Done when/Related, else at the end.
  - `archive`: the archived form. `pr` is an int or None (None leaves out the parenthesis; with None a pointer holding `#<digits>` is refused, since ShiftLead's `ANY_PR` would read it as the PR). `as_is=True` keeps Fix and puts the `**Resolved:**` line after the whole Fix section. No section named exactly Fix: the line goes at the end of the body, and a qualified Fix lead is left alone. An existing `**Resolved:**` section is replaced, never doubled; a header `Resolved` is removed; a missing Status is added.
  - `reopen`: Status `Open YYYY-MM-DD: why — was: <old>` (no `— was:` clause if there was no Status). The `**Resolved:**` section stays; a header `Resolved` moves into it, never deleted. An entry with both a header `Resolved` and a `**Resolved:**` section is refused: merge them by hand, then reopen (Paul, 2026-10-30: no entry in either consumer's ledger has both, and a new section no reader knows would change which date and PR the entry reports). Fix is not rebuilt: the caller follows with `edit fix`.
  - `renumber`: rewrite the heading's id. `rename_ref`: rewrite `old` to `new` in `Blocked by` and `Part of`.
- **No `field_problems()`:** writers refuse only on form; validity stays in `check()`/`pickable()`, which the caller runs on the result.
- **`check()` gains `archive-open-parts`:** given `old=`, an id that left the ledger while an open entry is still `Part of` it is an error naming the parts. Like `rank`, it is never demoted to standing.
- **Dates are passed in** (`today=`). Link depth on archive and v1 ledgers stay out: the consumer relinks, and every writer refuses v1 with "split first".
- **Tests:** invented fixtures in `fixtures/ledger_edit/`, with `fixtures/run.py` extended to run them: `canonical` idempotent; each refusal; each action round-trips; section extents (Fix with bullets, qualified lead, unnamed lead); `archive-open-parts` never standing; archive and note with no Status; archive with no Fix or only a qualified one; archive after reopen (one `**Resolved:**`); archive and reopen with a header `Resolved`; `edit fix` after reopen; CRLF input.
