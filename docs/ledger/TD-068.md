## TD-068: No writer retitles an open entry, and edit writes a section named as a header field

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-11
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** 6df1c3e5e8ec42b2bb7ea773b5aa9166

**Why:** No writer changes an open entry's title, and `edit` and `set` write a section or a field under any name, `Title` and a header field's included. The title lives only in the `## TD-n: title` heading (`SPEC.md` *The ledger as a directory (v2)*, *Ledger entries and their edits*), and the edits (`ENTRY_ACTIONS`: `set`, `note`, `edit`, …) each keep "the same id, title, fields and sections but for the change", so none can retitle. `edit` (`section`, `words`) adds a section the body lacks and, beside an empty or multi-line name or empty words, refuses only a name two sections share and the Log; `set` (`fields`) sets or adds any field. So `ledger.py edit TD-n --section Title --from FILE` writes a body paragraph `**Title:** <words>` and leaves the heading as it was, and `--section Status` writes a body `**Status:** …` beside the header's `**Status:**` field and `set TD-n --field Title=…` writes a header field `**Title:** …` under the unchanged heading (all three reproduced on 2026-11-11 against `main`). None is refused, and `--check` reports none.

The harm: when a split or a redesign changes an entry's scope, its title can only be fixed by hand, which the cadence forbids (a session writes the ledger only through the helpers), or by deleting the file and filing it again with `ledger.py new --id` under the same id, which drops its Log and history. A mistyped section name leaves a stray paragraph that reads like a field and is not one.

Found by ShiftLead's session `ao-shiftlead-td-1551` (mail m-187a27755a0f, about ShiftLead TD-1551, 2026-11-11): splitting ShiftLead's TD-1664 changed its scope; `edit --section Title` wrote a body `**Title:**` field under the old heading, and the session deleted the file and filed it again under the same id. It asked for a `set --title` (or an edit of the heading), and for `edit` to refuse a section name that is a header field or unknown to SPEC, with tests.

**Location:** ledgerboard/__init__.py (edit_entry, ENTRY_ACTIONS, entry_text, check); ledgerboard/ledger.py (set, edit); SPEC.md (Ledger entries and their edits; The ledger as a directory (v2); Versions); fixtures/ledger_edit/; tests/

**Fix:** A design round first (Kind design-first): it adds an edit to `SPEC.md` *Ledger entries and their edits* and narrows `edit`, so its shape is the design's. What the design settles:

- The retitle: a new action in `ENTRY_ACTIONS` (or a `title` argument to `set`), its refusals (an empty or multi-line title, as `entry_text()` refuses), its Log line if it writes one, and its command line in `ledgerboard/ledger.py` (`set --title` or its own verb). The file keeps its name (`SPEC.md` *The ledger as a directory (v2)*: "a retitle never renames a file").
- Which section names `edit` refuses, and which field names `set` refuses: `Title` (the title lives only in the heading) and, for `edit`, the header fields (the core fields and the `Fields:` line's own) at the least. Refusing every name SPEC does not list would also refuse sections the format already takes (`Ask`, `Event (<name>)`, `Related`, a repo's own), so the design decides whether there is such a list.
- Whether `check()` flags an existing body section named as a header field, and whether either change is a version event under `SPEC.md` *Versions*.
- Its fixtures in `fixtures/ledger_edit/` (a retitle; `edit` refused for `Title` and for a header field; `set` refused for `Title`) and unit tests in `tests/`.

Then the build(s) the design files, each landing its `SPEC.md` text with its code and fixtures; then a release (Paul's), agent-cadence's vendor PR and ShiftLead's sync PR.

**Done when:** A release of ledgerboard in which an open entry's title is changed through a writer (its heading rewritten, its file, fields, sections and Log kept), `edit` refuses a section named `Title` or as a header field, and `set` refuses a `Title` field, with `SPEC.md`, fixtures and tests for each; the precheck green.
