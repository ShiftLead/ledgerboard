## TD-070: Evaluate and design the board as a directory, one file per item with a stable id, for v3.0

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-11
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** d0f07979d5dc4da68a5c295e6f675fa0

**Why:** The board is one file, and `board.py add` writes every new item at the same place: above the first item of its section (`_under()`, `plan_add()`). Two PRs that each add an item therefore always conflict, and GitHub's merge runs no merge driver, so each collision is a rebase and a full precheck again. No layout inside one file avoids it: two inserts at one anchor conflict wherever the anchor is. agent-cadence's TD-248 (2026-11-07) gave the rebase a tool, `board_edit.py replay`, which removes the hand edit but not the rebase or the precheck, and its closing note left the layout to this repo.

The v2 ledger split (*The ledger as a directory*) ended the same problem for entries. Measured on 2026-11-11 from the git output in one machine's session transcripts since 2026-10-12: about 140 conflict events on v1 ledger files, 3 on v2 ledger directories, and 7 on boards (a floor: ShiftLead's TD-1482 counted more than six board rebases in one burst of design PRs, one PR rebased three times). So the board's conflicts are real and far rarer than the ledger's were; they alone do not justify a major.

The case for the directory is the item's shape. A `decide` item is now a line of one to two kilobytes with a detail block and a life of its own (open, decided, closed, archived), which is an entry's shape. Its identity is the item key, the line with some fields cut out, which consumers persist and which no release may change within a major. One file per item, named by a stable id, would replace the key with the id, turn the archive into a file move (`archive_closed()`, its refusals and `ARCHIVE_AT` go), and end both the open-and-closed-twin rule and `replay`. Collisions also grow with the number of PRs open at once, which is rising.

It is a major: a v2 reader cannot read a directory. Paul asked for the evaluation on 2026-11-11 and asked for this entry.

**Location:** SPEC.md (The board; Edits; The board writer; The merge gate's verdicts; Versions); ledgerboard/__init__.py (item_key, parse_board, archive_closed, board_problems, tripwire, lift_pr_verdict, BOARD_PATH); ledgerboard/board.py; fixtures/board/, fixtures/board_writer/, fixtures/edit/; docs/plans/target-design.md (§7.1 the v3.0 row)

**Ask:** Say Go to start the design round for the board as a directory (one file per item, a stable item id, for v3.0), or Not yet to leave it until v2.7 is out and the rebases `replay` still costs have been counted.

**Fix:** A design round first (Kind design-first), for v3.0, decided on the format's long-term merit and not on today's conflict count or on what a migration costs. What the design settles:

- **The item id**, first: what names an item's file and replaces the item key (a counter as *The next id*, a hash of the v2 key, or a date and a nonce), how a v2 key a consumer holds maps to it, and whether the key stays readable for one major.
- **The layout**: the directory, its preamble file (`People:`, `Answered by:`, the stamps), the sections (`## Needs the user`, `## In-flight`), the archive as a subdirectory, and the order of items, which `needs_you()` and the writers read from the file today.
- **Reading**: a `load()`-like join that gives the parsers, `sweep()` and `covers()` one text, as the ledger's does, and whether one call reads either major.
- **What rested on one line changed in one file**: the five edits and `--line`/`--expect`; `board_problems(board, old)`; `tripwire()`, `uncovered_decisions()` and `lift_pr_verdict()`'s condition (b); `BOARD_PATH` and `BOARD_ARCHIVE_PATH`; the commit subjects; and, in the consumers, the carve-outs that judge a commit by its touching the board alone.
- **Reading from a forge**: a board is one file read today; a directory is a listing and a read per item, or one tree read.
- **What a person reads**: with no single file, which view replaces it.
- **Migration**: a `split()` for a v2 board and its archive, and its place in v3.0's order (the target design's §7.1 v3.0 row).
- **Whether to do it at all**: the design may conclude that the single file with `replay` stays; the count of rebases `replay` still costs between now and then is its evidence.

Then the builds the design files, each with its `SPEC.md` text, code and fixtures.

**Done when:** A reviewed design in `docs/plans/` that either specifies the board as a directory for v3.0 (the item id, the layout, reading, the writers, the gate's verdicts, migration) with its builds filed as parts of this entry, or records why the single file stays; Paul's answer to its end-of-rounds item.
