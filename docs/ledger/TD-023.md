**Why:** Target design §6 *Hide until* asks that `item_problem()` note (ℹ) a `Hide until` in the past and one later than the item's `Due:`. TD-017's build (PR for TD-017) leaves both out: `item_problem(line)` takes no `today`, and it has no channel for a note. Everything it returns is a fault, which `board_problems()` (the merge gate) refuses, while §6 asks for an ℹ that informs.

**Ask:** Say Go to file TD-023's one build (a new `item_notes()` reported beside the board's gate, in v2.4), One more round for another review, or Hold with a note.

**Fix:** [the plan](../plans/TD-023-hide-notes.md). It adds a new `item_notes(item, today)` that no gate reads, rather than a `today` on `item_problem()`, since SPEC's gate judges a line once, when it is added. It has two rules: `hide-spent` (a `Hide until` that hides nothing today) and `hide-late` (a hidden item whose hide is after its `Due:`). `item_record()` carries the notes as `notes`, and `board.py` reports them for the line a write leaves, never refusing. One build, in v2.4 (v2.3 was tagged without it). It is filed on Paul's go, and its Fix carries round 2's fixes F11–F17, which no review has read (*fixed, not reviewed; the builder checks it*). No consumer needs to change.

**Done when:** the design is reviewed (`docs/reviews/TD-023.md`), Paul has said go on its board item, and its build is filed `**Part of:** TD-023`. The design entry archives with that build.
