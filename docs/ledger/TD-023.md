**Why:** Target design §6 *Hide until* asks that `item_problem()` note (ℹ) a `Hide until` in the past and one later than the item's `Due:`. TD-017's build (PR for TD-017) leaves both out: `item_problem(line)` takes no `today`, and it has no channel for a note. Everything it returns is a fault, which `board_problems()` (the merge gate) refuses, while §6 asks for an ℹ that informs.

**Ask:** Say Go to file TD-023's one build (`item_notes()` reported beside the board's gate, in the next release after it lands), One more round, or Hold with a note; the round Paul bought is done.

**Fix:** [the plan](../plans/TD-023-hide-notes.md). It adds a new `item_notes(item, today)` that no gate reads, rather than a `today` on `item_problem()`, since SPEC's gate judges a line once, when it is added. It has two rules: `hide-spent` (a `Hide until` that hides nothing today) and `hide-late` (a hidden item whose hide is after its `Due:`). `item_record()` carries the notes as `notes`, and `board.py` reports them as `item_notes` for the line a write leaves, never refusing (a decide lift's existing `notes` key is unchanged). One build, in the next release after it lands: v2.4 if before its tag, else v2.5 (Paul, 2026-11-04); TD-036 does not wait on it. It is filed on Paul's go, and its Fix carries round 3's minor fixes F28–F32, which only the closing fact-check read (*fixed, not reviewed; the builder checks it*); round 3's design review read F11–F17 and F20–F27. No consumer needs to change.
